# Запросы на подключение источников — бот «Тайный гость»

Кому что отправить, чтобы бот получил данные. Каждый блок — готовый текст
для пересылки. Что нужно от источника, что уже готово со стороны бота,
и как это подключается (в большинстве случаев — файлом в чат с ботом).

Статус на 16.09.2026. Ссылка на ТЗ: `docs/ТЗ-тайники-v1.1.md`, раздел 20.

---

## 1. Syrve — интегратор / IT

**Закрыто 16.09:** доступ проверен на живых данных — заказы, поиск по
телефону, номенклатура, стоп-листы работают текущим ключом Cloud API.
Glovo-заказы опознаются по позиции «Сервісний збір_Glovo» в составе.
Запрос интегратору **не нужен**. Остаётся только ABC-выгрузка.

**ABC-продажи.** Через Server API (OLAP) бот не ходит: лицензия даёт три
сессии, их держит Core. Вместо этого — выгрузка раз в месяц файлом:

> **Запрос (бухгалтерия / кто делает отчёты в Syrve).** Раз в месяц
> выгружать отчёт по продажам блюд за прошлый месяц в CSV с колонками
> `syrve_id;назва;кількість;виручка` и отправлять файлом с именем
> `abc-2026-09.csv` в чат с ботом @mystery_shopper_Cappi_bot.

## 2. Loopa (Review360) — разработчики (высокая, этап 2)

> Loopa — своя (`~/code/Review360`), ТЗ передано напрямую в сессию
> «Dev setup configuration» 16.09; рассылать не нужно.

**Уже сделано:** бот читает негатив по филиалам и категориям
(`/metrics/reviews`, как Core) и использует его при генерации заданий.
**Раздел «Тайники» в Loopa** (макет утверждён 16.09) строится поверх
HTTP API бота — Loopa ничего не хранит, только рисует и шлёт решения.
Спецификация: `docs/API.md`.

> **Запрос в Loopa.** Для раздела «Тайники» (макет согласован) данные
> отдаёт бот тайного гостя по HTTP API — спецификация приложена
> (`API.md`): вкладки Черга / Хвилі / Перевірки / Тайники / Виплати /
> Еталони / Аналітика / Правила читаются GET-ами, решения (принять /
> на доработку / отклонить, выплачено, активировать, открыть волну,
> правила) — POST-ами. Авторизация Bearer-токеном, роль в `X-Role`,
> кто решил — в `X-User`. Адрес: сервер cappi-bot, порт 8788 на
> localhost — нужен проксирующий location в nginx Loopa (или отдельный
> поддомен с TLS), токен передадим отдельно.
>
> От Loopa нужен один endpoint записи — тикеты (Loopa их владелец):
>
> `POST /api/v1/mystery/tickets` (Bearer-токен тот же, что для `/metrics/reviews`)
> ```json
> {"check_id": "П-0012", "branch": "Лазарєва", "channel": "Сайт",
>  "title": "Червона зона: холодна страва", "description": "…",
>  "due": "2026-09-20", "test": false, "source": "mystery-shopper-bot"}
> ```
> Ответ: `{"id": "<id тикета в Loopa>"}`. Поле `test: true` — «тестовое
> обращение»: тикет виден маркетологу, но исключается из статистики
> жалоб, компенсаций и бонусов (ТЗ, раздел 12). Закрытие тикета в Loopa
> — `POST /api/tickets/<id>/close` в бот, чтобы агент запланировал
> повторную проверку.

## 3. HR — список сотрудников (высокая, этап 1)

Нужен для верификации кандидата: не сотрудник и не родственник.

> **Запрос в HR.** Список телефонов всех действующих сотрудников (кухня,
> курьеры, операторы, администраторы, офис) — по одному номеру в строке,
> любой формат записи номера. Файл назвать `співробітники.txt` и
> отправить в чат с ботом @mystery_shopper_Cappi_bot. Обновлять при
> найме/увольнении или раз в месяц. Бот хранит только последние 9 цифр,
> имён не нужно.

**Со стороны бота:** файл принимается, при регистрации кандидата
маркетолог сразу видит «телефон есть в списке сотрудников».

## 4. Шеф-повар — база эталонов (блокирующее, этап 1)

Без эталона позиция в задание не попадает. Нужны топ-30 по продажам,
все новинки и акционные позиции.

> **Запрос шефу.** Таблица эталонов (Google Sheets, экспорт в CSV UTF-8,
> разделитель «;»), колонки:
>
> `id;назва;категорія;статус;версія;ціна;шматків;упаковка;температура;склад;комплектність;ознаки;фірмове;syrve_id;запущено`
>
> - `категорія`: суші та роли / піца / WOK / напої та допи / новинки / акційні
> - `статус`: опубліковано або чернетка (чернетки в проверку не идут)
> - `комплектність` и `ознаки` — списки через «|»
> - `ознаки` — 3–5 признаков, на которые неспециалист ответит «да/нет»:
>   «Зріз рівний», «Начинка по центру», «Борт піднявся», «Локшина не злиплась»
> - `фірмове` — по чему блюдо узнаётся как каппівське (соус, топпинг, нарезка)
> - `шматків` — норма кусков (маки 6, inside-out 8)
> - `температура`: гаряча / холодна; `упаковка`: пенал / коробка / контейнер
>
> Файл `еталони.csv` отправить в чат с ботом. Образец —
> `еталони.приклад.json` в репозитории. Эталонные фото (в упаковке, без,
> в разрезе) — следующим шагом, отдельной папкой.

**Со стороны бота:** импорт CSV, привязка к номенклатуре Syrve по
названию (`/еталони`), из признаков собираются вопросы анкеты по каждой
позиции задания.

## 5. Маркетинг — правила программы, новинки и акции (этап 1)

**Решить (открытые вопросы ТЗ, раздел 23):** ставка за анкету, предел
компенсации заказа, лимит бюджета в месяц, срок хранения фото (сейчас
180 дней), кто координатор поддержки и кто подменяет на выходных.
Всё это меняется из бота: «⚙️ Правила програми».

> **Запрос маркетингу (до подключения CappiX).** Список новинок и акций
> файлом `новинки.csv`: `назва;syrve_id;тип;від;до`, где `тип` —
> новинка или акція, `від`/`до` — даты. Обновлять при каждом запуске.
> Новинка попадает в проверку не раньше чем через 7 дней после `від`.

> **Запрос в CappiX (этап 2).** Нужен endpoint или выгрузка: новинки с
> датой запуска и составом, действующие акции с периодом и условиями,
> календарь кампаний. Формат — JSON, читаем раз в сутки. Пока нет — ведём
> руками файлом выше.

## 6. Операции — график смен (средняя, этап 2)

Без графика оценка «кухня Лазарева» остаётся обезличенной, повторяющийся
паттерн по сотруднику не виден. Оператор и курьер по заказу уже берутся
из Syrve; кухня — только из графика.

> **Запрос администраторам филиалов.** Раз в неделю файл `зміни.csv`:
> `дата;філія;роль;імя` — кто работал на кухне в каждый день. Отправлять
> в чат с ботом. Видит только маркетолог; в рабочие чаты имена не идут.

## 7. Glovo (средняя, этап 2)

> **Запрос интегратору Glovo/Syrve.** Подтвердить, что Glovo-заказ
> однозначно опознаётся в Syrve Cloud API (по `sourceKey` или
> `marketingSource`), и что телефон клиента из Glovo попадает в заказ —
> иначе сопоставить проверку с заказом нельзя. Доступ к меню Glovo
> (позиции, цены, фото, доступность) — если есть partner API, нужен токен
> на чтение; иначе сверку меню делает тайник скриншотами.

Со стороны бота: канал Glovo, блоки анкеты и отдельные группы оценки
готовы; включается в «Правилах», когда сопоставление подтверждено.

## Что подключается без чьего-либо участия

| источник | как |
|---|---|
| Syrve Cloud | уже; проверить `/syrve` |
| Loopa чтение | уже |
| OpenAI (сводки, поддержка) | уже, ключ из Core |
| эталоны, HR, новинки, смены, ABC | файлом в чат с ботом |
| Loopa запись тикетов | `LOOPA_WRITE=1` в api.env после ответа Loopa |
| Loopa читает бота | `SHOPPER_API_TOKEN` в api.env + nginx location |
| Core → «тайный гость» | бот пишет `для_core.json` в своей папке данных; Core может читать его вместо ручного ввода |
