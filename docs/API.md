# HTTP API бота для розділу «Тайники» в Loopa

Бот — джерело даних, Loopa — інтерфейс компанії (ТЗ, розділ 19).
Loopa нічого не зберігає: читає JSON і малює вкладки; рішення людини
шле POST-ом, бот виконує їх як натискання кнопки в Telegram — з
журналом, повідомленням тайнику, звітами в чати.

**Адреса:** `http://127.0.0.1:8788` на сервері `cappi-bot` (назовні —
через nginx з TLS, домен узгодити). **Авторизація:** `Authorization:
Bearer <SHOPPER_API_TOKEN>`. **Роль:** `X-Role: marketer | admin |
viewer` — без marketer/admin персональні дані тайника (ім'я, телефон,
Telegram, реквізити) не віддаються і POST-и відхиляються (403).
**Хто вирішив:** `X-User: <логін>` або `"who"` у тілі — потрапляє в журнал.
Усі відповіді — JSON UTF-8. Ідентифікатори: П-0001 (перевірка), В-0001
(виплата, той самий номер), Т-001 (тайник), Х-001 (хвиля), Т001 (тікет).

## Читання

| GET | що | вкладка макета |
|---|---|---|
| `/api/queue` | `{kpi, черга:[…]}` — лише те, що потребує рішення людини: кандидати, анкети на ревю (з `критично`, `автоперевірок_не_пройдено`), доробки, виплати без переказу/підтвердження, незайняті слоти | Черга |
| `/api/kpi` | перевірок за місяць, на ревю, червона зона, виплати чекають, середня оцінка, витрачено/ліміт, активних тайників | KPI-рядок |
| `/api/waves`, `/api/waves/Х-001` | хвилі зі слотами (тайник — Т-номер), чергою (з рейтингом 0–100), кількістю відгуків | Хвилі |
| `/api/analytics` → `матриця` | факт покриття за квартал по зрізах і порядок відставання — звідси агент бере зріз наступної хвилі | Хвилі → матриця |
| `/api/checks?month=2026-09&status=&branch=` | список перевірок: статус, філія, канал, вікно, позиції, провокація, оцінка, зона, замовлення Syrve, сума, виплата, рекомендація агента | Перевірки |
| `/api/checks/П-0001` | картка цілком (див. нижче) | Картка перевірки |
| `/api/media/<file_id>` | фото з анкети (проксі до Telegram, JPEG) | Картка → Медіа |
| `/api/shoppers`, `/api/shoppers/Т-001` | реєстр: статус, район, канали, перевірок, рейтинг (1–5 і 0–100), остання, кулдаун до, зриви, блеклист; картка — з історією перевірок і статусів | Тайники |
| `/api/payouts` | `{бюджет:{витрачено, ліміт, середня, залишок}, заявки:[…]}` — статус, чек і джерело чека (Syrve/анкета), компенсація, ставка, разом, історія | Виплати |
| `/api/payouts.csv` | реєстр для закриття місяця | Виплати → вивантажити |
| `/api/etalons` | база еталонів: версія, джерело, картки з syrve_id, покриття по категоріях | Еталони |
| `/api/analytics` | динаміка по групах по тижнях, обіцяно/факт (медіана, у межах, найбільше), тайники проти клієнтів (оцінка ↔ скарги Loopa за 30 дн по філіях), матриця, негатив Loopa | Аналітика |
| `/api/monthly?month=2026-09` | текст місячної зводки і `для_core.json` | Аналітика |
| `/api/rules` | усі налаштування (ваги груп, зони, слоти, кулдаун, тайм-аути, ставка, ліміти, канали), версія анкети, таблиця меж автономії агента | Правила |
| `/api/tickets` | тікети бота: перевірка, чому, тестове, закрито, повторна перевірка | Черга / Перевірки |
| `/api/journal?object=П-0001` або `?limit=100` | журнал рішень агента і людей з «чому» | Картка → Прогрес |
| `/api/support` | звернення тайників у підтримку, SLA | — |

### Картка перевірки `/api/checks/П-0001`

```

завдання            — ТЗ цілком: позиції з еталонами, бюджет, докази, памятка, сценарій провокації, обґрунтування агента
анкета.блоки[]      — блок → питання[]: код, питання, тип, група, відповідь, показ (людський текст), позиція, вага, критично
приймання           — автоперевірки [{що, ок: true|false|null, деталь}], бракує, рекомендація, чому
syrve               — знайдено, замовлення {номер, статус, філія, створено, підтверджено, відправлено, доставлено,
                      обіцяно_до, факт_хв, обіцяно_хв, сума, позиції, оператор, курєр}, збіги {…}, відсутні_позиції
оцінка_повна        — загальна, зона, групи {назва, відсоток, зона, критичні[]}, критичні[], час_доставки_хв,
                      запізнення_хв, джерело_таймингу (Syrve|анкета), ваги
медіа[]             — {код, підпис, file_id, url}
історія[]           — зміни статусу {коли, з, у, хто, чому}     ← вкладка «Прогрес»
журнал[]            — записи агента по цій перевірці
виплата_повна       — номер, статус, чек, джерело_чека, компенсація, ставка, разом, історія
тайник_картка       — з персоналіями лише для marketer/admin
```

## Рішення (POST, лише marketer/admin)

| POST | тіло | що робить |
|---|---|---|
| `/api/checks/П-0001/decision` | `{"action":"accept"}` · `{"action":"rework","reason":"…"}` · `{"action":"reject","reason":"…"}` | те саме, що кнопки в Telegram: оцінка, заявка на виплату, звіти в чати, повідомлення тайнику; 409 — якщо статус не «на ревю» |
| `/api/payouts/В-0001/paid` | `{}` | адміністратор переказав; тайнику йде запит «гроші прийшли?» |
| `/api/payouts/В-0001/reject` | `{"reason":"…"}` | відмова у виплаті з підставою |
| `/api/shoppers/Т-001/activate` · `/pause` · `/blacklist` | `{"reason":"…"}` для blacklist | зміна статусу; тайника повідомляють |
| `/api/waves` | `{"action":"create","open":false}` | нова хвиля за матрицею покриття (чернетка або одразу набір) |
| `/api/waves/Х-001/open` | `{}` | відкрити набір: запрошення тайникам |
| `/api/rules` | `{"ставка_за_анкету":80, "ліміт_замовлення":750, …}` | будь-які ключі з `/api/rules`, крім чатів і довідників; кожна зміна — у журнал |
| `/api/tickets/Т001/close` | `{}` | виправлено → повторна перевірка того ж зрізу першим слотом наступної хвилі |

## Що лишається за Loopa

- **Тікети.** Loopa — власник тікетів. Бот шле `POST /api/v1/mystery/tickets`
  (контракт у «Запитах до джерел», п. 2) і чекає `{"id"}`; поки endpoint-а
  немає, тікет живе в боті (`/api/tickets`) і йде маркетологу текстом.
- **Ролі.** Хто marketer, хто admin, хто керівник точки (лише читання по
  своїй філії) — вирішує Loopa і ставить `X-Role`; фільтр по філії —
  `?branch=` у `/api/checks`.
- **Мобільний вид** і п'ятий пункт нижньої панелі зі лічильником —
  лічильник = `len(черга)` з `/api/queue`.
